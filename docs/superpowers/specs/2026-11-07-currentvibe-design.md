# CurrentVibe 설계 (MVP)

날짜: 2026-11-07

## 1. 의도
GitHub에서 요즘 뜨는 저장소를 웨일 사이드바에서 바로 훑어보고, 마음에 드는 저장소를 **AI에게 분석부터 시키는 정형화된 프롬프트**로 복사하는 웨일 확장 프로그램.

지금은 저장소 주소를 복사해서 AI에게 "이거 적용해줘"라고 보내는데, 그러면 AI가 분석 없이 바로 적용을 시작한다. CurrentVibe는 **적용하기 전에 분석, 이점, 사용 가능한 환경을 먼저 보도록** 흐름을 바꾼다.

웨일 확장 스토어에 공개 배포할 예정이다.

## 2. 목표 / 비목표 / 실패 기준
**목표**
- 사이드바에서 GitHub Trending 순위를 Daily, Weekly, Monthly로 본다.
- 저장소마다 열기, 주소 복사, 프롬프트 복사를 한 번의 클릭으로 한다.
- 복사한 프롬프트는 어떤 AI 도구(Claude, ChatGPT, Cursor, Codex 등)에 붙여 넣어도 동작한다.

**비목표 (MVP 이후로 미룸)**
- 프롬프트 커스텀(템플릿 편집)
- 프로그래밍 언어 필터
- 백엔드(Supabase 등), 로그인, 사용 통계

**실패 기준 (동작하더라도 실패로 보는 경우)**
- 복사한 프롬프트를 받은 AI가 분석 없이 바로 코드를 수정한다.
- 사이드바가 느리게 열리거나, 순위를 불러오지 못하면 빈 화면만 보인다.
- 로그인이나 API 키를 요구한다.

## 3. 제약
- **플랫폼:** 네이버 웨일 확장. Chrome 확장 표준(Manifest V3)에 웨일 전용 `sidebar_action`(사이드바 페이지)을 더한다.
- **기술:** 프레임워크와 빌드 과정 없이 HTML, CSS, JavaScript만 쓴다.
- **백엔드 없음:** 확장이 `https://github.com/trending` 페이지를 직접 받아서 필요한 정보를 뽑는다(`host_permissions`에 `https://github.com/*`).
- **나중을 위한 분리:** 순위를 가져오고 읽는 코드는 한 모듈에 모은다. 나중에 Supabase 등으로 옮길 때 그 모듈만 바꾸면 되게 한다.

## 4. 사용자가 정한 것
### 화면 (A안: 촘촘한 목록)
- **다크 모드 고정:** 블랙 바탕에 퍼플 포인트. 웨일 테마와 관계없이 항상 어둡다.
- **상단:** Daily / Weekly / Monthly 탭. 오른쪽 위에 **KOR / ENG 토글**.
- **목록 항목 (한 줄씩 촘촘하게):**
  - 순위 번호, `owner/repo` 이름
  - 전체 Star 수와, 그 옆에 해당 기간 동안 늘어난 Star 수(퍼플 강조, 예: `+1.2k`)
  - 설명 한 줄
  - 오른쪽 아래 동작: 🔗 열기(새 탭), 📋 주소 복사, **프롬프트 복사**(강조 버튼)

### 언어 토글
- 토글하면 화면 문구와 복사되는 프롬프트가 함께 바뀐다.

### 프롬프트
AI가 **바로 적용하지 않고** 다음 내용을 먼저 출력한 뒤, 적용할지 묻고 멈추게 한다.
1. 저장소 요약: 무엇이고 어떻게 동작하는지
2. 적용 가능 여부: 지금 내 프로젝트나 환경에서 쓸 수 있는지
3. 사용 가능한 환경: 어떤 AI 도구와 환경에서 쓸 수 있는지(예: Claude Code CLI 전용인지, 데스크톱 앱이나 웹에서도 되는지, Cursor 등 다른 도구에서는 어떻게 쓰는지), 설치 형태(스킬, 플러그인, MCP 서버, 일반 라이브러리 등)
4. 적용했을 때의 이점
5. 적용 방법 개요, 단점, 주의할 점
6. 적용할지 묻고 멈추기

프롬프트는 특정 AI에 묶이지 않는 범용 문구로 쓴다. 저장소 정보가 들어갈 자리는 `{{url}}`, `{{name}}`, `{{description}}`으로 표시한 템플릿 형식으로 둔다(나중에 커스텀 기능을 붙이기 쉽게).

**한국어 기본 프롬프트 (초안)**
```
아래 GitHub 저장소를 분석해줘. 아직 코드나 설정을 수정하지 마.

저장소: {{name}}
주소: {{url}}
설명: {{description}}

다음 순서로 정리해줘.
1. 요약: 이 저장소가 무엇이고 어떻게 동작하는지
2. 적용 가능 여부: 지금 내 프로젝트와 환경에 적용할 수 있는지, 그 이유
3. 사용 가능한 환경: 어떤 AI 도구나 환경에서 쓸 수 있는지(예: Claude Code CLI, Claude 데스크톱 앱, claude.ai 웹, Cursor, ChatGPT, Codex 등), 설치 형태(스킬, 플러그인, MCP 서버, 라이브러리 등)
4. 이점: 적용했을 때 얻는 것
5. 적용 방법: 단계 개요와 예상 변경 범위, 단점과 주의할 점

위 주소를 열 수 없다면 추측하지 말고, README 내용을 붙여 달라고 나에게 요청해.
내 프로젝트나 환경을 볼 수 없다면, 2번에 답하기 전에 내 환경(사용 중인 AI 도구, 언어, 프레임워크)을 먼저 물어봐.

분석이 끝나면 적용할지 나에게 묻고, 내가 승인하기 전까지 아무것도 변경하지 마.
```
영어 프롬프트는 같은 구조를 영어로 옮긴다.

**프롬프트에 담는 정보:** 이름, 주소, 한 줄 설명만 담는다(README는 담지 않음). 복사는 추가 요청 없이 즉시 된다. 링크를 못 여는 AI는 위 문장에 따라 사용자에게 README를 요청한다.

### 최종 목표: 웨일 확장 스토어 등록
MVP는 스토어에 등록할 수 있는 상태까지 만든다. 등록에 필요한 파일(웨일 개발자 센터 "등록 준비" 기준):
- **확장앱 패키지:** 확장 폴더를 압축한 ZIP 파일. 개발용 파일(테스트, `node_modules`, `package.json`, `docs`)은 빼고 확장에 필요한 파일만 담는다.
- **아이콘:** 128 × 128px PNG.
- **스크린샷:** 1~4장, 1280 × 800px, JPG 또는 PNG.
- 이미지가 권장 크기보다 작으면 고해상도 화면에서 흐리게 보이므로 권장 크기에 맞춘다.

## 5. 빌더 판단에 맡긴 것 (내 판단으로 정한 기본값)
- 목록 개수: GitHub Trending 페이지에 나오는 만큼(보통 25개).
- 캐시: 기간별 결과를 잠깐(예: 10분) 저장해서 탭을 오갈 때 빠르게 보여준다. 사이드바를 새로 열면 오래된 캐시는 새로 받는다.
- 설명이 길면 한 줄로 자르고 말줄임(…) 처리한다. 설명이 없는 저장소는 설명 줄을 생략한다.
- 복사 후 버튼에 잠깐 "복사됨 ✓"을 표시한다.
- 언어 기본값: 웨일 언어가 한국어면 KOR, 아니면 ENG. 마지막 선택은 `chrome.storage`에 기억한다.
- 불러오기 중에는 로딩 표시를, 실패하면 오류 문구와 "다시 시도" 버튼을 보여준다.
- 아이콘과 세부 색상 값(블랙, 퍼플 계열)은 빌더가 정한다.
- 테스트: 핵심 로직(Trending HTML 파싱, 프롬프트 템플릿 채우기)은 TDD로, UI는 웨일에 실제로 로드해서 확인한다.
- **[빌더 판단] 테스트 환경:** 개발용으로만 Node와 npm을 쓴다(`node:test` + `linkedom`을 devDependency로). 파서는 확장 안에서 `DOMParser`를 쓰고, 테스트에서는 linkedom으로 같은 코드를 돌린다. 배포되는 확장은 빌드 없는 순수 파일 그대로다. 테스트 데이터는 실제 Trending 페이지 HTML을 저장한 파일로 쓴다.
- **[빌더 판단] 스토어 제출물:** 아이콘은 직접 만든 단순한 퍼플 로고로 하고, 매니페스트용 작은 크기(16, 48px)도 함께 만든다. 스크린샷은 실제 웨일 사이드바 화면을 캡처해서 1280 × 800px로 맞춘다(2장 이상: 목록 화면, 복사 동작). ZIP은 확장 파일만 담는 간단한 스크립트로 만든다. 스토어 계정 가입과 실제 제출 버튼은 사용자가 직접 한다.
- **[빌더 판단] 프롬프트 검증:** 완성된 한국어와 영어 프롬프트를 실제 AI 도구 두 곳 이상(예: Claude Code와 ChatGPT)에 붙여 넣어서, 분석만 하고 멈추는지 확인한다. 문제가 있으면 문구를 고친다. 최종 확인은 사용자가 한다.
